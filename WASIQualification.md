# Swift6.4 WASI browser qualification

This isolated branch starts at SQLiteData1.12.0 (164bb5f223738af3d5da7a1b8de14e67e4d9cd5d). It imports Dispatch explicitly and buffers custom aggregate inputs on WASI, reducing during SQLite xFinal. The native streaming/NSCondition path remains unchanged. Generic inputs use the original Sequence aggregate API; finalization caches success/error and releases the buffer; group state is independent. WASI memory cost is proportional to each aggregate input count, so production callers need explicit bounds. This is not thread emulation.

GRDB is pinned to the same qualified source on lake-of-fire/GRDB.swift branch wasm/browser-6.4-20261003 at24c1edc802eff363f5737d6f4c22197bd8d212f2, adopted from PassiveLogic (MIT). Dispatch source pin: PassiveLogic/swift-corelibs-libdispatch dbf44d65057673570df974394fb699230582644c, compiled with official Swift.org6.4 and matching official WASM SDK. The host must register a later-turn scheduler and perform budgeted Dispatch work; fake inline queues are not valid. The GRDB default DatabasePool is not qualified; inject explicit DatabaseQueue.

Actual Chromium141 worker tests pass typed model/query/update/rollback, UUID/Date/BLOB/null/near-maxInt64 codecs, FetchAll non-Combine, commit observation/rollback silence/cancel, scalar functions and synchronous/asynchronous aggregates with GROUPBY and empty input. A Swift reactor also passes real browser microtasks/timer delivery. Native iOS simulator typed/aggregate/observation/reopen tests pass with the original native stream. These are bounded synthetic tests, not a claim that arbitrary package/platform APIs, localized DateFormatter, durable storage or a production app are ready.

Examples/WASI/SQLiteDataProbe.swift is the generic synthetic conformance source actually executed in the isolated consumer. Its DispatchHost pump is a test-only top-level scheduler fixture; real production scheduling requires asynchronous host turns. The consumer also supplied same-memory public-domain SQLite3.53.4 and an in-memory fixture VFS; no separate JavaScript SQLite engine executed these queries. Official SDK does not supply a browser OPFS implementation. WASM wasm32 Int cannot represent large server identities: use explicit Int64 and serialize safely at JSON boundaries.

The prior fork/default branch is unchanged. No application/owned domain source, credentials or customer data is included. Remote dependency URL replaces the locally tested sibling-path configuration while retaining the exact same GRDB revision; a clean remote-fetch graph rerun remains separate from the recorded compiled source/runtime qualification.
